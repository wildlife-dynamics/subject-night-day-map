Troubleshooting

Common issues while configuring, running or changing subject-day-night-map, and how to resolve them.

Configuration & running

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to the data the workflow asks for.

The Subject Group Name drop-down is empty

The list comes from the data source chosen under Connect to EarthRanger, so pick that first. If it stays empty, the connection can't be reached or its account can't see any subject groups.

The run returns no data

Check the Subject Group Name picked is the group you meant, and that it has location fixes in the time range. Widen the time range if it's short.

Every segment is the same colour

All fixes fell on one side of sunset, e.g. a short daytime-only time range, or a collar that only reports by day. Widen the time range to cover full days.

Tracks look broken up, or long jumps are missing

Segments outside the Trajectory Segment Filter limits are dropped. Loosen the limits under Relocations To Trajectory (advanced) for fast-moving or rarely reporting subjects.

There's one map but I expected one per subject

Add a Category → Subject Name grouper under Set Groupers.

Developing

The Subject Group field is free text instead of a drop-down

Check the override key matches the step id, subjectgroup_observations.properties.subject_group_name, and that its depends_on points at properties.er_connection.properties.data_source.properties.name, then recompile.

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-subject-day-night-location-map-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
